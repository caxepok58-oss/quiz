# Пенза Квиз-бот

Telegram-бот на [aiogram 3](https://docs.aiogram.dev/), который раз в сутки собирает
расписание квиз-игр в Пензе на ближайший месяц из нескольких сайтов и по команде
показывает таблицу: дата, время, игра, место проведения.

## Источники данных

Найдены поиском (действующие квиз-сети, у которых есть отдельные страницы расписания по Пензе),
проверены вживую против реальных сайтов:

- **Квиз, плиз!** (`bot/sources/quizplease.py`) — сайт (`penza.quizplease.ru`) сам является
  Nuxt-приложением и тянет расписание из собственного публичного JSON API:
  `https://api.quizplease.ru/api/games/schedule/85` (`85` — числовой id Пензы, вытащен из
  Nuxt-пейлоада страницы). Точный парсинг JSON, без эвристик.
- **Шейкер квиз** (`bot/sources/shakerquiz.py`) — сайт (`penza.shakerquiz.ru`) на Next.js,
  сервер сам встраивает ответы своего API в `<script id="__NEXT_DATA__">` на странице
  (`props.pageProps.store`, ключи `GET/games/search` и `GET/games/venue/:venue/search`,
  которые тут джойнятся по `game_id`). Тоже точный парсинг JSON.
  `event_time` в API приходит в UTC (суффикс `Z`) — бот конвертирует в `Europe/Moscow`;
  это не перепроверено против человекочитаемого времени на самой площадке (на статической
  странице его просто нет), так что если по факту игры стартуют не в те часы — уберите
  конвертацию в `ShakerQuizSource.parse`.
- **Клуб «60 секунд»** (`bot/sources/club60sec.py`, `bot/sources/heuristic.py`) — обычный
  server-rendered сайт (Django + jQuery + `tablesorter` для таблиц), без SPA/API. На момент
  разработки расписание игр в Пензе у этой сети было пустым (`Нет ближайших игр`), поэтому
  проверить точную вёрстку заполненной таблицы вживую не вышло. Источник ищет в тексте
  страницы русские даты/время по регуляркам (`bot/text_parsing.py`) и берёт наименьший
  подходящий блок (включая `<tr>`, что должно подойти под их `tablesorter`-таблицы) как
  карточку одной игры. Когда там появятся реальные игры — проверьте `/sources`, и если
  результат кривой, добавьте этому источнику отдельный класс с точными селекторами вместо
  `HeuristicScheduleSource` (по образцу `quizplease.py`/`shakerquiz.py`).
- **BrainSurf** (`bot/sources/brainsurf.py`) — сайт `brainsurf.ru/penza/` редиректит на
  `penza.brainsurf.ru` (обычный WordPress, без SPA). Каждая игра — карточка
  `.schedule-item` со стабильными классами (`.schedule-item__title`, `.src-date_time`,
  `.schedule-icon--location`, `.schedule-icon--price`), парсинг точный, не эвристика.
  Карусель (swiper) дублирует карточки — источник дедуплицирует их сам.
- **МАМАКВИЗ!** (`bot/sources/mamaquiz.py`) — `penza.mamaquiz.ru` собран на Tilda: у каждого
  поля (заголовок, описание, место, адрес, время, цена) свой абсолютно спозиционированный
  `<div>` без общей обёртки-карточки на игру, так что нет чистого CSS-селектора одной игры —
  надёжен только порядок чтения текста. Поэтому парсинг через регулярку по всему тексту
  страницы, а названия площадок сверяются со списком известных баров Пензы (`_VENUES` —
  те же бары, что фигурируют у quizplease/shakerquiz/brainsurf), а не парсятся обобщённо.
  Если МАМАКВИЗ начнёт проводить игры в новом баре — добавьте его в `_VENUES`.
- **Вау Квиз** (`bot/sources/wowquiz.py`) — правильный URL оказался `pnz.wowquiz.ru`
  (не `penza.wowquiz.ru` / `wowquiz.ru`, которые смотрел раньше). Сайт — Nuxt SPA без
  единого байта SSR-данных, весь рендеринг клиентский. API-домен (`api.etowow.ru`,
  бэкенд на Yii2) — общий для многих городских франшиз "Wow Quiz"; `GET /games/all` без
  параметров отдаёт вперемешку игры ВСЕХ городов (`pageCount` в районе 160). Нужный
  фильтр нашёлся в минифицированном JS-бандле: каждый запрос сайта проходит через
  `onRequest`-хук, который добавляет query-параметр `domain=<window.location.origin>` —
  т.е. `domain=https://pnz.wowquiz.ru` фильтрует именно на пензенскую франшизу
  (`franchise_id=206`). Точный парсинг JSON, без эвристик.
- **Мозгобойня** — рабочего источника найти не вышло. Официальная площадка Ruda Games
  (`rudagames.com`, тоже Nuxt SPA, бэкенд `api.rudagames.com`) вообще не упоминает Пензу
  нигде на странице расписания. `mzgb.pro` — отдельный сайт под тем же названием, но это
  Челябинск, не Пенза. На агрегаторе findquiz.ru у пензенского организатора «Мозгобойня»
  значится 0 игр. Похоже, франшиза сейчас не проводит игры в Пензе ни через один доступный
  для парсинга сайт. Сейчас это заглушка (`bot/sources/unavailable.py`), которая честно
  показывает причину в `/sources` вместо того, чтобы молча притворяться, что игр нет —
  добавляйте игры этой франшизы через `/add_game`, если найдёте живой источник.

Список источников — `bot/sources/__init__.py`. Добавить ещё один сайт: новый файл-класс
(на основе `BaseSource`, `HeuristicScheduleSource` или точного JSON-парсинга — смотря что
у сайта под капотом) + добавить его в `ALL_SOURCES`.

Есть надёжный запасной путь, не зависящий от парсинга сайтов вообще — ручное добавление
игр администратором (`/add_game`).

### Почему curl, а не aiohttp

Квиз, плиз! / Шейкер квиз / Клуб «60 секунд» отдают `403 Forbidden` библиотеке `aiohttp`
(и `requests`, и `curl_cffi` в конфигурации из коробки) даже с браузерным `User-Agent` —
похоже на фильтрацию по TLS/HTTP-отпечатку клиента антибот-защитой. Обычный системный
`curl` с тем же `User-Agent` проходит стабильно (проверено многократно). Поэтому
`bot/http_client.py` делает HTTP-запросы через `curl` в подпроцессе, а не через `aiohttp`.
Из-за этого боту нужен установленный `curl` в `PATH` (он есть практически на любом Linux-сервере).

## Команды бота

Кнопки в главном меню (`bot/keyboards.py`) дублируют самые частые команды — `/games` на
7/30 дней, `/favorites`, `/remind_games`, `/remind_on`/`/remind_off` (кнопки включают
напоминания с шагом по умолчанию — 3 часа) и `/update` — печатать команды вручную не
обязательно. Свой интервал (`/remind_on 5`) и `/remind_status` доступны только командой.

- `/start` — приветствие и список команд.
- `/games` (или `/quizzes`) — таблица всех игр на ближайшие `LOOKAHEAD_DAYS` дней. Если в `/favorites`
  отмечены франшизы, показывает только их (плюс всегда — ручные записи). Внизу последнего
  сообщения — отметка о свежести данных («обновлены N мин/ч назад», по времени последнего
  успешного обновления хотя бы одного источника).
- `/favorites` — inline-клавиатура для выбора интересных франшиз; фильтрует, что показывает
  `/games` (и какие игры видны в `/remind_games`). Каждая франшиза — тоггл-кнопка (✅/⬜),
  плюс кнопка сброса до «показывать все».
- `/remind_games` — inline-список игр по дням (◀️/▶️ листать день за днём) с тоггл-кнопкой
  на каждую игру — отмечаете конкретные игры, о которых хотите узнать заранее. Напоминания
  приходят **только** по отмеченным играм, не по всем подряд. Если ни одна игра не выбрана,
  напоминаний не будет, даже при включённых `/remind_on`.
- `/remind_on [часов]` — за сколько часов до игры присылать напоминание (по умолчанию 3, 1-24).
  Включается автоматически при выборе первой игры в `/remind_games`, если ещё не была настроена.
- `/remind_off` — выключить напоминания (выбранные в `/remind_games` игры сохраняются).
- `/remind_status` (или `/remind`) — посмотреть текущую настройку и число выбранных игр.
- `/sources` — статус последнего обновления каждого источника (сколько игр нашлось). Если
  источник падает 3 дня подряд, админам (`ADMIN_IDS`) сразу приходит алерт в личку —
  не нужно заходить в `/sources` вручную, чтобы это заметить (см. ниже).
- `/schedule_image` — JPEG-картинка с таблицей **всех** игр (без учёта `/favorites`) на
  30 дней вперёд: каждая франшиза — свой цвет фона строки (в тексте Telegram цвет фона
  невозможен в принципе, а в картинке — можно, см. «Картинка с расписанием» ниже).
- `/update` — force-refresh всех источников (только админы, `ADMIN_IDS`).
- `/add_game ГГГГ-ММ-ДД ЧЧ:ММ Название | Место | Цена` — добавить игру вручную (админы).
- `/list_manual` — список вручную добавленных игр с их id (админы).
- `/del_game <id>` — удалить вручную добавленную игру (админы).

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите в .env токен бота от @BotFather и свой Telegram id в ADMIN_IDS

python run.py
```

Переменные окружения (`.env`):

| Переменная      | Назначение                                   | По умолчанию   |
|-----------------|-----------------------------------------------|----------------|
| `BOT_TOKEN`     | Токен бота от @BotFather                      | —              |
| `ADMIN_IDS`     | Telegram id админов через запятую              | —              |
| `CITY_NAME`     | Название города в сообщениях                  | `Пенза`        |
| `TZ_NAME`       | Часовой пояс для расписания обновлений        | `Europe/Moscow`|
| `LOOKAHEAD_DAYS`| На сколько дней вперёд показывать игры        | `30`           |
| `SCRAPE_HOUR`   | В какой час (по TZ_NAME) обновлять данные раз в сутки | `6`    |
| `DB_PATH`       | Путь к файлу SQLite                           | `quizzes.db`   |
| `BOT_PROXY_URL` | Прокси для связи с Telegram (см. ниже)        | не задан (прямое соединение) |

При старте бот сразу обновляет данные один раз, затем — каждый день в `SCRAPE_HOUR`.

### Если `api.telegram.org` заблокирован у вашего провайдера

Бот использует `curl` для сайтов с квизами (см. выше), но с самим Telegram общается через
`aiogram`/`aiohttp` напрямую. Если у вас `api.telegram.org` не открывается вообще (проверить:
`curl -v https://api.telegram.org` — таймаут вместо ответа), а обычный VPN-клиент не помогает
(проверьте, что это системный VPN, а не расширение браузера — IP должен меняться:
`curl https://api.ipify.org` до/после включения VPN), но при этом у вас уже есть VPN-приложение
вроде Happ/V2rayNG с локальным SOCKS5/HTTP прокси — впишите его адрес в `.env`:

```
BOT_PROXY_URL=http://127.0.0.1:10809
```
или для SOCKS5:
```
BOT_PROXY_URL=socks5://127.0.0.1:10808
```

(порты возьмите из настроек своего VPN-приложения — это его локальный inbound-прокси).
Бот подключится к Telegram через этот прокси; сайты квизов при этом продолжат ходить напрямую
(им прокси не нужен).

## Данные и хранение

SQLite-файл (`DB_PATH`) с таблицами:

- `events` — то, что нашли скрейперы (перезаписывается на каждое обновление, отдельно по источнику).
- `manual_events` — то, что руками добавил админ через `/add_game` (не трогается скрейпером).
- `source_status` — статус последнего запуска каждого источника, для `/sources` и алертов
  админам (`consecutive_failures`/`last_failure_date`/`alerted` — счётчик дней подряд).
- `favorites` — какие франшизы отметил себе каждый чат через `/favorites` (фильтр отображения).
- `reminder_settings` — у кого включены напоминания и за сколько минут до игры.
- `game_reminders` — какие конкретные игры отметил себе каждый чат через `/remind_games`.
- `sent_reminders` — какие напоминания уже отправлены (чтобы не дублировать).

Игры с датой в прошлом чистятся автоматически при каждом ежедневном обновлении (вместе со
старыми записями в `sent_reminders` и `game_reminders`).

### Напоминания

`bot/reminders.py` раз в 15 минут (`bot/scheduler.py`) проверяет игры на сегодня/завтра и
шлёт разовое напоминание в чаты, где включено `/remind_on`, **только** по играм, явно
отмеченным через `/remind_games` (таблица `game_reminders`) — не по всем играм подряд и не
по франшизам. `/remind_games` показывает список игр одного дня с тоггл-кнопками; кнопки
◀️/▶️ листают дни. Ссылка на конкретную игру в кнопке — `id` строки в `events`/`manual_events`
(меняется при каждом пересборе расписания), но сама подписка в `game_reminders` хранится по
стабильному `Event.dedup_key()` (для ручных игр — `manual-<id>`), поэтому она не теряется и
не дублируется между обновлениями расписания. Список игр в `/remind_games` уважает текущий
фильтр `/favorites`, если он задан.

### Алерт админу при падении источника

`bot/db.py: Database.set_source_status` считает подряд идущие неудачные обновления
каждого источника (`ALERT_AFTER_DAYS = 3`). Несколько неудачных запусков в один и тот же
календарный день (например, ручные повторы `/update`) считаются одним днём — это защита от
ложного срабатывания через час-два, а не через 3 реальных дня. Как только источник падает
3-й день подряд, `bot/aggregator.py` шлёт каждому админу (`ADMIN_IDS`) сообщение с текстом
ошибки — один раз на весь простой, не каждый день заново. Счётчик и флаг «уже
предупредили» сбрасываются, как только источник снова отдаёт данные, так что при повторном
падении алерт придёт снова (через те же 3 дня).

### Картинка с расписанием

`bot/schedule_image.py` (`Pillow`) рисует таблицу расписания как обычное растровое
изображение, а не текст — благодаря этому можно раскрасить фон каждой строки по
франшизе (`_ROW_COLORS`), чего в тексте Telegram сделать нельзя в принципе (там нет
цвета текста/фона — см. обсуждение раньше про попытки раскрасить строки эмодзи). Заголовок
игры и место переносятся на 2 строки при необходимости, высота строки/картинки
считается заранее под фактический текст — картинка не обрезается и не съезжает вне
зависимости от длины названий. Отдаётся строго через `/schedule_image`, без фильтра
`/favorites` — это специально «полное» расписание.

Шрифт (`bot/assets/fonts/DejaVuSans*.ttf`) закладывается прямо в репозиторий, а не берётся
из системы: как выяснилось на Railway, в образе Railpack не оказалось даже `curl`
(см. ниже), так что рассчитывать на предустановленные системные шрифты с поддержкой
кириллицы тоже нельзя. Эмодзи в текст картинки не добавляются — у DejaVu Sans нет
цветных emoji-глифов, вместо символа получился бы пустой квадрат-«тофу».

### Почему long polling, а не webhook

Бот получает обновления от Telegram через `dp.start_polling(bot)`, а не через webhook.
Webhook снял бы постоянное соединение и был бы чуть экономнее по ресурсам, но требует
публичного HTTPS-домена, слушающего порта (`$PORT`) и отдельного класса ошибок при деплое
(неверный домен/секрет → бот молча не получает обновления вообще, в отличие от polling,
где сбой хотя бы виден в логах). Учитывая, что это бот на один город с несколькими
пользователями, а не высоконагруженный сервис, а на Railway разворачивание уже несколько
раз ломалось на других вещах (`Procfile`, отсутствующий `curl`, переменные окружения) —
polling выбран как более простой и предсказуемый вариант. Переход на webhook возможен,
но это отдельная, более рискованная задача — если понадобится, обсудите отдельно.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыты регулярки для дат/времени, сборка таблицы для Telegram и парсеры всех источников
с рабочим скрейпером (`quizplease`/`shakerquiz`/`wowquiz` — на фикстурах реальной формы
JSON, `brainsurf`/`mamaquiz` — на фикстурах реальной HTML/текстовой формы, `heuristic` — на
синтетической HTML-заготовке). Живых интеграционных тестов на реальные сайты нет, но код
парсеров был вручную прогнан против реально скачанных страниц/API-ответов в процессе
разработки (см. вывод `/sources` — по состоянию на момент написания: `quizplease` — 11 игр,
`shakerquiz` — 12, `brainsurf` — 10, `mamaquiz` — 7, `wowquiz` — 8, `club60sec` — 0 (сейчас
правда нет игр в Пензе), `mozgoboynya` — 0 с объяснением причины вместо тихого нуля).
